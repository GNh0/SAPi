# Shadow observation and in-memory real-input boundary

No production Site, D1 database, monitor or network route is changed by this code. No real traffic has been acquired or evaluated. The earlier `import_shadow_observations.py` and `examples/shadow/adapter.mjs` exercise a **synthetic fixture mapping** using only classifications; their local tests are not actual-attack results. The adapter emits no traffic itself. `handleWithShadow` returns the original response even when observation raises, and its queue, sampling and counters are bounded. Its generated UUID is a shadow observation ID; integrating it with an existing server request ID requires a separately designed trusted boundary. Callers must drain the queue separately and account for process shutdown, delivery failures and overflow; this example does not claim complete collection or zero latency impact.

For the user's actual-input goal, `tools/evaluate_shadow_memory.py` provides an isolated **in-process function**, not a deployed receiver. A trusted caller may pass the original method, origin-form path, bounded body bytes, content type and limited length/framing metadata, together with a server-generated UUID, source observation time and original response status. It accepts only `body_relation` of `original`, `masked`, `transformed`, or `unknown`; this is a caller assertion, not independently verified. It accepts only a boolean for Authorization presence and never receives an authorization value. The body remains an input object in memory; paths and bodies, credentials, query strings, external addresses, tokens, and personal data are never written into its result DB. Python may copy bytes and the OS may swap or dump memory: this is not secure erasure. Reject unsafe inputs upstream and establish memory, crash-dump, isolation, privacy and retention controls before any live use.

The raw input is evaluated only under the listed constraints. Bodies over 8192 bytes, unknown media/methods or a length mismatch are recorded `unsupported`, with no handler invocation. XML content is never parsed or entity-resolved; the existing transport gates reject it. For accepted combinations, the in-memory comparison calls the same extracted pure SAPi and baseline transport predicates used by the local listeners. Baseline JSON without a credential is rejected at the modeled authentication entry; a credential-present request is `not_measured` because the credential is deliberately unavailable. Where a bounded SAPi wire reaches its gate, the actual SAPi `Application.handle` is called with a freshly generated, process-local test key and Python sockets/SAPi egress disabled for that call. A wire rejection under this isolated key is **not** evidence the same wire would fail with production keys. The business handler is deliberately blocked; the only DB-state probe is a synthetic in-memory sentinel. The original endpoint response remains an observed, separate fact, not the outcome of the local experiment. Returned status is the projected result of the local transport/handler logic, not an observed HTTP response from a listener. Origin/CORS, metadata-byte limits, peer limiting, timeouts, and actual socket parsing are not supplied to this model and are not measured.

`evaluate(request, db_path)` writes one `input_observations` record and three `in_memory_results` rows in a single transaction. Results include source vs isolated provenance, caller-declared original/masked/transformed/unknown relation, original status, normalized outcome, inferred stage, bounded counters, before/after sentinel digests, explicit limitations and an egress observation. The DB stores no input bytes or raw path. A repeated UUID increments `duplicate_count` and returns `duplicate_unverified` without executing again; no raw-body hash is retained, so the system cannot establish whether duplicate bytes were identical. Reject input with unexpected keys, invalid UUID/timestamp/types or overlong path before writing. This function patches Python socket construction only during SAPi handling; it must run in a dedicated isolated process, never in a shared production request handler. This guard is not an OS-wide sandbox, and native/file side effects are not measured.

```sql
SELECT o.request_id, o.observed_utc, o.path_class, o.method_class, o.media_class,
       o.size_bucket, o.original_status, o.body_relation, o.body_persisted,
       r.variant, r.result, r.inferred_stage, r.http_status,
       r.gateway_calls, r.business_attempts, r.business_state_changed,
       r.outbound_observation, r.provenance, r.limitation
FROM input_observations o JOIN in_memory_results r USING(request_id)
ORDER BY o.observed_utc, r.variant;
```

The synthetic classification importer has a 64 KiB batch and 64-event bound, strict feature enum/shape/type checks, bounded counters, UUIDs, duplicate batch and request checks, and conflicting-identity rejection. Unknown categories remain `unsupported`; only a static allowlist maps to a local fixed fixture. It stores source features and local fixture outcomes under separate provenance. Sampling percentage, sampled-out, queue-dropped, observer-error and saturation counts are self-reported; they do not prove source completeness. A synthetically reconstructed fixture is never the original request and cannot establish a production exploit outcome.

Tests use invented inputs only:

```text
python -m unittest discover -s tests -p test_shadow_memory.py -v
python -m unittest discover -s tests -p test_shadow_import.py -v
```

Before any real connection, separately resolve authorization and architecture: how to authenticate the source and bind a server-generated ID, safely transfer bounded original bytes into a dedicated isolated process without changing the live response, preserve fail-open/backpressure and loss accounting, enforce OS-level no-network/no-file-external-resource restrictions, handle secrets/PII and retention, prevent replay into production, and evaluate the actual deployment's baseline and SAPi key/trust models. This Python function cannot be directly inserted into a different Site runtime without an approved bridge or a separately implemented equivalent. Inbound unauthenticated scans alone cannot measure post-authenticated scope, ownership, replay or business-state protection. Any real-world conclusions require an authorized connection and genuine observations, which do not exist in these local test artifacts.

## Worker-compatible SDK investigation

`examples/shadow/worker-inspector.mjs` accepts bounded bytes and explicit injected test key/replay providers, uses the actual ESM `Codec`/`SecureServer`, registers no application operations, returns only fixed outcome classes and never calls `fetch`. `tests/test_worker_inspector.mjs` uses a Node VM context with WebCrypto and no `process`, `require`, `fetch` or allowed non-file/dynamic imports. It exercises a valid message, duplicate, tamper and size limit. This is a compatibility probe, not execution in Sites Worker or proof of deployability. The SDK's conditional `node:crypto` branch is not used by that probe; `state-node` and filesystem/mTLS modules are not imported. `MemoryReplayStore` is per-process and not safe as a distributed replay guarantee. No D1 implementation or production key is provided. See `AUDIT_EVIDENCE.md` for the unverified atomic-state and deployment requirements.
