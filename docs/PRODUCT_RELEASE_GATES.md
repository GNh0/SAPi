# Technical quality and evidence review

This document records the evidence and gaps to check with the rigor of an external security review. It is not a sales or commercial release plan. The filename is retained to preserve existing links. Evidence applies to its revision and environment; earlier tests do not automatically establish results for later changes. Priorities identify blockers for the GNho comparison and reliable use of SAPi.

| Priority / area | Current evidence | Work or evidence still needed |
| --- | --- | --- |
| P0 — real inbound comparison | Local synthetic fixtures and a bounded input contract; no GNho traffic has been connected. | Obtain authorized Site source/deployment route and agree the insertion point and source `request_id`. Implement a separately isolated, bounded, loss-accounted bridge and preserve actual versus transformed provenance. Evaluate real inputs without changing the live response; independently review the results. Unauthenticated scanning only measures pre-auth stages. |
| P0 — defensible security effect | Three loopback configurations, shared business implementation, 675 synthetic observations from one local run. Replay and message-integrity controls have different configuration and trust assumptions. | Compare equivalent policies and clearly identify differences, controls, coverage and unmeasured outcomes. Validate real inputs and relevant authenticated paths with dummy identities. Obtain independent security review and resolve material findings; no general superiority or guaranteed protection is established. |
| P0 — safety and observability | Metadata-only local evidence, bounded synthetic queue, no production ingress or D1 integration. | Threat-model source authentication, privacy, retention, safe memory handling and OS-level egress/file isolation; measure losses, latency and resource ceilings. Prove failure isolation under exhaustion and outage. Link input, stages, outcome, dummy DB state and observable effects without exposing credentials or raw sensitive data. |
| P0 — distributed state and keys | VM test demonstrates replay state is per `MemoryReplayStore`; static key counters are local. `state-node` uses Node filesystem and HTTPS. State Authority documents issuance, rotation and revocation. | Verify the selected Worker runtime and bundler, key provisioning and lifecycle, durable atomic replay and rate decisions, reservation limits, concurrent instances, outage and recovery. D1 suitability and its adapter remain unverified. Do not use the VM result as production proof. |
| P1 — dependencies and license | Repository has dependency-audit evidence from earlier revisions; `CONTRIBUTING.md` states no project license has been selected. | Update the dependency inventory and vulnerability review, resolve relevant findings, and clarify project and third-party license terms where distribution is considered. Prior audit is time-bound. |
| P1 — functional parity | Synthetic orders manifest covers 18 normal and error steps across three configurations with matching state digests. All share one orders implementation. | Define the selected API contract, operations, data, error and concurrency semantics; independently verify every in-scope function and state transition in the target environment. Current result does not prove arbitrary API parity. |
| P1 — developer migration | `OPT_IN_MIGRATION.md` and a Python in-process proof preserve an existing callable with explicit modes. | Validate actual framework and clients, key configuration, policy equivalence, failure mapping, staged rollout and rollback. Do not allow silent fallback; no one-click conversion or Worker integration is established. |
| P1 — maintenance and data evolution | `COMPARISON_MAINTENANCE.md` records dependencies and debt. Local comparison, parity and shadow stores have versioned schemas and copy-only legacy migrations. | Independently review the shadow migration; separate stable baseline, orchestration and storage contracts; test hosted migrations and rollback; review failure diagnostics and configuration. Existing local evidence must be preserved. |
| P1 — installation, operations and recovery | Application and state installation/operations documents exist, plus earlier compatibility evidence. | Reproduce installation and upgrades on supported environments; document configuration, least privilege, key custody, backup, restore, failure and recovery procedures; exercise outage, saturation and data recovery with objective acceptance criteria. |
| P1 — compatibility and supply chain | Historical alpha.4 platform and packaging results exist; JS SDK VM probe uses Node WebCrypto without network. | Establish a supported matrix and rerun the selected revision in each target runtime, including actual Sites packaging. Verify artifact provenance and dependency updates. |
| P1 — independent review | Repository describes internal review and explicitly says it is not an external security audit. | Agree review scope, independently check findings and fixes, and document residual uncertainty and recovery responsibilities. No independent certification is claimed. |

The immediate work is to obtain the authorized Site source, prepare the isolated comparison patch and have its deployment scope reviewed. This document does not authorize production changes or new services.
