# 보안 모델

SAPI/0.1은 신뢰한 클라이언트·서버와 클라이언트별 32바이트 공유 키를 사용합니다. AES-GCM 인증은 키의 소유를 검증합니다. 양쪽 키 소유자 모두 메시지를 생성할 수 있으므로 공개 검증 가능한 서명이나 부인 방지를 제공하지 않습니다.

## 메시지와 처리 경계

보호 헤더·서비스·키 ID·방향을 원본 AAD로 인증하고 본문을 암호화합니다. 엄격한 JSON, 크기, 시간, 재전송 ID, scope, 입력 validator, 객체 권한 policy를 검사합니다. 서버는 업무 함수를 호출하기 전에 응답 암호화 키와 사용량 한도를 예약합니다. 예약 실패 시 업무를 시작하지 않습니다.

재전송 예약은 만료 시간까지 한 번의 실행 시도를 허용합니다. 업무 DB의 커밋과 예약은 별도 거래이므로 업무의 정확히 한 번 처리는 멱등성 키·업무 거래 계약으로 구성합니다. 예약 후 업무 시작 전에 중단된 요청도 다시 실행하지 않습니다.

## 영속 상태와 키 수명

`StateClient`는 mTLS 상태 서비스를 키 공급자와 재전송 저장소로 사용합니다. 서비스는 키를 AES-256-GCM으로 저장하고, DB 밖의 KEK와 감사 키를 사용합니다. 발급·키 조회·예약·회전·폐기·재전송 예약을 비밀 값 없이 감사 기록에 남깁니다.

SQLite는 단일 호스트의 여러 프로세스에서 사용합니다. PostgreSQL은 여러 상태 서비스의 공통 저장소입니다. DB 쓰기 잠금과 외부 체크포인트를 공유하는 모든 상태 서비스의 사용량과 재전송 예약을 합산합니다. 메시지 방향별 한도는 최대 2^20회이며 기본 TTL은 하루입니다. 활성 키 조회 시 사용량 80% 또는 만료 180초 전부터 자동 회전합니다.

회전한 키는 새 요청 암호화가 중단되고 최대 120초간 기존 요청 복호화·응답 암호화를 허용합니다. 폐기는 해당 키의 저장된 암호문을 제거하고 이후 조회·예약·처리를 거부합니다. 이미 키를 조회하고 처리에 진입한 업무를 취소하거나 다른 메모리/백업에서 키를 물리적으로 삭제하는 기능은 아닙니다.

`StaticKeyProvider`와 `MemoryReplayStore`는 격리된 예제·단일 프로세스용입니다. 영속 상태를 사용하는 배포는 `StateClient`를 두 계약에 연결합니다. 임의 클라이언트는 이미 가진 PSK로 SDK 밖에서 메시지를 만들 수 있으므로 사용량 한도는 관리된 구현의 암호화 사용량에 대한 계약입니다.

## 상태 무결성과 복구

외부 체크포인트의 HMAC은 감사 기록의 순서·마지막 태그, 단조로운 시간 기준, 인증 자료구조의 루트를 묶습니다. 키·루트 키 사용량·활성 키 포인터·재전송 ID/만료/개수는 그 자료구조에 연결됩니다. 과거 DB 복원, 과거의 정상 레코드 복원, 재전송 행 삭제, 카운터 수정은 검증된 현재 상태와 일치하지 않으면 거부합니다.

체크포인트를 DB 잠금 보유 중 먼저 fsync/교체하고 SQL을 커밋합니다. 이 사이 장애가 나면 서비스는 거부 상태를 유지합니다. `recover`는 원본 파일을 보존하고 새 KEK·감사 키·빈 DB를 생성합니다. 기존 키를 가져오지 않으며 관리자가 명시적으로 재발급합니다.

체크포인트와 KEK·감사 키는 DB 백업과 별도로 보호합니다. 이 신뢰 영역까지 과거로 되돌리거나 관리자 권한·감사 키를 탈취한 경우에는 상태 검증의 신뢰 근거도 잃습니다. PostgreSQL 복제본은 같은 최신 체크포인트를 읽고 원자적 교체·flush를 보장하는 공통 저장소를 사용해야 합니다. 실제 스토리지의 전원 장애 내구성은 배포 환경에서 확인합니다.

## 연결과 인증서

API 데이터 연결은 HTTP·HTTPS를 지원합니다. 키와 재전송 상태를 다루는 관리 연결은 HTTPS/mTLS만 허용합니다. 인증서 체인·용도·만료·호스트 이름을 검증하고 등록된 클라이언트 인증서 fingerprint에 관리자/서비스/클라이언트 역할과 서비스·주체 범위를 연결합니다. 인증서 제거·등록 변경은 운영 설정을 갱신하고 서비스 재시작으로 적용합니다.

HTTP에서는 URL·외부 헤더·IP·길이·시간이 노출되고 차단·지연이 가능합니다. HTTP로 처음 받은 실행 코드나 공개 키를 신뢰하면 안 됩니다. 브라우저에는 신뢰한 HTTPS 배포 코드와 보안 컨텍스트가 필요하며 CORS·혼합 콘텐츠 제한을 우회하지 않습니다. 브라우저 번들에 공유 키·개인 인증서를 넣지 않습니다.

## 범위

장기 PSK 유출 뒤 과거 메시지를 보호하는 전방향 비밀성, 사용자 로그인·SSO·MFA, 침해된 단말/서버, 암호화 전·복호화 후 평문 유출은 이 규격의 보호 범위가 아닙니다. 객체 소유권 등 업무 정책은 서버가 명시적으로 등록합니다.

[검증 기록](../docs/VALIDATION.md)과 [독립 에이전트 검토](../docs/SECURITY_REVIEW.md)는 특정 소스와 조건의 증거입니다. 정식 외부 감사 기관의 인증이나 모든 운영 환경의 안전성 보증은 아닙니다.
