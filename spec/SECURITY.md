# 보호 범위와 운영 전 요구사항

## 신뢰 경계

SAPI/0.1은 사전에 신뢰할 수 있게 설치한 클라이언트/서버와 안전하게 발급한 클라이언트별 PSK를 전제로 한다. AES-GCM 인증은 해당 키의 소유를 확인한다. 공유 키의 양쪽 소유자 모두 메시지를 만들 수 있으므로 제3자에게 발신자를 입증하는 서명/부인 방지를 제공하지 않는다.

한 클라이언트에 유출된 키는 해당 클라이언트를 사칭할 수 있다. 키는 사용자/앱/서비스 사이에 재사용하지 않고, server key registry가 키 폐기·권한과 주체를 결정해야 한다. HTTP로 처음 받은 공개 키나 실행 코드를 그대로 신뢰해서는 안 된다.

## 제공하는 보호

표준 암호 구현을 사용해 본문의 기밀성과 무결성을 검사한다. 보호 헤더, 서비스, kid, 방향과 암호문을 묶으며, 시간 제한과 요청 ID 저장으로 인증된 메시지의 재사용을 차단한다. 응답은 원래 요청의 해시와 ID에 묶는다. 명시된 입력/권한 정책을 통과한 경우에만 등록된 handler를 호출한다.

재전송에 대해 보장하는 것은 검사 범위 내 한 번의 **실행 시도**다. DB 커밋과 캐시 예약 사이의 장애를 처리하는 정확히 한 번의 업무 거래 처리는 제공하지 않는다. 재시도/멱등성은 별도의 업무 계약이다.

## 제공하지 않는 보호

- HTTP의 URL/헤더/IP/길이/시간 메타데이터 은닉, 전송 차단·지연·DoS 방지.
- 나중에 장기 공유 키가 유출돼도 예전 암호문을 보호하는 전방향 비밀성.
- 잘못 작성된 소유권 policy, 서버/클라이언트 침해, 악성 라이브러리, 로그의 평문, 암호화 전/복호화 후 정보 유출.
- 사용자 로그인, SSO, MFA, 토큰 서버와 동적 키 발급.
- 브라우저의 HTTP 실행 코드 변조 방지. Web Crypto 사용 가능 여부와 HTTPS 페이지의 HTTP fetch 차단 등 브라우저 정책 우회.
- 아직 구현/검증하지 않은 언어·프레임워크나 운영 배포의 자동 호환 보장.

## 프로토타입 제한

기본 재전송 저장소는 단일 프로세스의 제한된 메모리 저장소다. 프로세스 재시작/여러 복제본에서 동일 키를 사용하는 운영 환경에는 그대로 사용할 수 없다. 서버가 중지됐다가 같은 키로 다시 시작되면 아직 유효한 요청을 다시 받아들일 수 있다. 운영에는 원자적 영속/분산 저장소 또는 재시작 시 키 교체와 대기 전략이 필요하다.

시간 기준과 키별 전역 암호화 한도/회전은 운영자가 보장한다. 핵심 SDK는 프레임워크 종속성을 줄이기 위해 업무 handler를 자동으로 외부에 공개하지 않는다. 어댑터에서 평문 우회 경로를 노출하지 않도록 별도 검토해야 한다.

운영 승격 전에 독립 보안 리뷰, 퍼징, 부하/분산 장애 검사, 키 발급·회전·폐기, 영속 재전송 저장소, 접근 정책 감사, 배포·패치 절차를 완료해야 한다. HTTPS를 쓸 수 있는 환경에서는 연결 보호도 추가하는 것이 바람직하다. 제공 데모는 인증서 검증을 끄지 않는다.
