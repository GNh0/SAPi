# 구현 계획과 완료 조건

사용자 목표: HTTP와 HTTPS 모두에서 API 메시지·처리 계층이 보안을 담당하고, 언어와 프레임워크에 종속되지 않는 체계를 GNh0/SAPi에 구현한다.

이번 결과물의 중심은 SAPI/0.1 언어 독립 규격과 확장 가능한 적합성 시험이다. .NET·Java·Python·JavaScript는 최초의 참조 SDK이며 지원 언어를 이 네 개로 제한하지 않는다. 각 SDK는 같은 메시지의 암호화·복호화, 검증 및 권한/입력 검사 후 서버 처리를 지원한다. 언어별 구현은 독립 배포 단위다.

완료 조건:

1. 규격과 신뢰 조건을 공개 문서로 명시한다.
2. 최초 참조 구현들이 공통 벡터를 일치하게 처리한다. 새 언어의 구현 절차와 시험 계약을 제공한다.
3. registry에 등록된 N개 구현의 요청/응답을 모든 N×N 조합으로 검사한다.
4. 변조, 다른 방향/대상, 만료, 잘못된 키, 재사용, 권한/입력 오류에서 업무 처리가 차단된다.
5. 실제 로컬 HTTP와 자체 CA를 사용하는 HTTPS에서 정상 교환을 확인한다. TLS 인증서 검증을 끄지 않는다.
6. 실제로 검증한 환경, 패키지 산출물, 미지원 영역과 운영 전 남은 작업을 기록한다.

초기 프로필은 사전 발급 공유 키(PSK) 기반이며 동적 키 협상, 전방향 비밀성, 사용자 로그인/SSO, 분산 영속 재전송 저장소, 일반 브라우저 키 발급은 이번 범위 밖이다. 암호 알고리즘 자체를 새로 만들지 않는다.
